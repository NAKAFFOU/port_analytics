# Chapter 4 Technical Dossier — Description of the System

Source of facts: the codebase on branch `audit/data-integrity`, as it
exists after the data-integrity refactor (removal of all real-organisation
data, rebuild of the synthetic 2020-2026 dataset, restructuring of the
Streamlit dashboard to six pages). Structured to align with the
dissertation's announced Chapter 4 sections (4.2-4.8). Contains verified
facts only — no academic framing or interpretation; that synthesis is left
to the dissertation text.

## 4.2 Design Requirements

Requirements actually covered by the system as it stands, grouped by type.

### Data requirements

- Ingest financial data from more than one accounting-source shape: a
  pre-allocated Oracle analytical-view source (`ORACLE_PBI_VIEWS`,
  `config/sources/oracle_pbi_views.yaml`) and a raw JD Edwards table
  source (`JDE_ORACLE`, `config/sources/jde_oracle.yaml`), behind a common
  adapter interface (`src/adapters/base.py`).
- Preserve the source amount, source currency, applied FX rate, rate date
  and provider alongside every base-currency amount, for audit
  (`amount_source`/`amount_base`/`fx_rate_to_base`/`fx_rate_date`/
  `fx_provider` columns — `src/db/schema.py`).
- Support multi-currency data (GBP, EUR, USD, XOF) with a single
  configurable analytical base currency (`currency.base_currency`,
  `config/settings.yaml`).
- Support both annual and monthly reporting granularity
  (`reporting_periods.period_granularity IN ('MONTH','YEAR')`).
- Contain **no data traceable to any real organisation** — every dataset
  loaded outside of a live Oracle connection is generated by
  `src/db/seed_demo.py`, seeded deterministically (`RANDOM_SEED = 42`).

### Process requirements

- Compute a two-phase cost allocation (Shared Service Centres → Operational
  Cost Centres → Port Service Lines) for the synthetic source
  (`src/pipeline/allocations.py`), and read pre-allocated results as-is for
  the Oracle-views source (`pipeline.oracle_views_are_preallocated: true`,
  `src/ingestion/oracle_views.py`) — the two paths share one KPI-formula
  module (`src/pipeline/kpi_formulas.py`) so a ratio's definition cannot
  drift between sources.
- Never recompute a sign inversion already applied by Oracle: the PBI_JDE
  views apply `* -1`/`/100`/`ROUND()` at the view level; Python parses
  `MONTANT` as returned and only takes an absolute value for cost display
  (`force_absolute` in `MEASURE_CONFIG`, `src/ingestion/oracle_views.py`)
  — never a second sign flip.
- Log every extraction (rows extracted/valid/loaded/rejected, filters
  used, duration, status) to `data_load_runs`, and every data-quality
  finding to `data_quality_issues`.
- Generate rule-based decision alerts after every KPI computation
  (`src/rules/alerts.py::generate_alerts`).

### Governance requirements

- No credentials in tracked files: `.env.example` contains placeholders
  only (`CHANGE_ME`); real values are read from environment variables /
  a local, gitignored `.env`.
- SQL access to the live Oracle source is by bind parameter only — column
  and object names come from the internal mapping
  (`src/adapters/oracle_source_mapping.py`), never from free-text input.
- Test isolation: `tests/conftest.py` redirects every test run to a
  dedicated SQLite file (`PORT_ANALYTICS_DB_PATH`) so the test suite can
  never reset or leave rows in the analyst's working database.

### User requirements

- Bilingual dashboard (English default, French toggle), all strings
  centralised in `src/dashboard/i18n.py`, no hardcoded UI strings in view
  files.
- A single, unchanged sidebar (language, year, period, display currency)
  shared by all six exposed pages (`src/dashboard/context.py`).
- Consistent colour coding of the same category across all six pages
  (`src/dashboard/viz_theme.py`).

## 4.3 Architecture Overview

Text diagram of the chain as it exists after the refactor. Two source
paths converge on the same analytical tables and the same dashboard.

```text
Synthetic path (DATA_SOURCE=synthetic):
  src/db/seed_demo.py::seed_demo()
        |  (SSC/OCC/PSL reference data, budgets, actuals, revenue,
        |   FX rates — 2020-2026, annual or monthly)
        v
  src/pipeline/allocations.py (two-phase allocation)
        v
  src/pipeline/kpi.py::compute_and_store_kpis()
        v
  src/rules/alerts.py::generate_alerts()
        v
  occ_indicators / psl_indicators / decision_alerts (SQLite)

Oracle-views path (DATA_SOURCE=oracle):
  Live Oracle connection (src/connectors/oracle.py)
        v
  src/adapters/oracle_pbi_views.py::OraclePBIViewsAdapter
    (5 read-only views in schema PBI_JDE; bind-parameter extraction only)
        v
  src/ingestion/oracle_views.py::ingest_frames()
    (validation, semantic mapping, currency conversion, no re-allocation)
        v
  oracle_view_facts -> occ_indicators / psl_indicators / decision_alerts

  Synthetic stand-in for the same path, no live connection required:
  src/db/seed_demo.py::generate_synthetic_oracle_views()
    -> data/import/oracle_views_sample/*.csv (exact PBI_JDE column layout)
    -> src/ingestion/oracle_views.py::run_oracle_views_sample_pipeline()

Both paths converge on:
  src/dashboard/data.py::load_dashboard_data()
        v
  src/dashboard/app.py (sidebar + 6-page routing)
```

## 4.5 Transformation Layer

### KPI formulas (`src/pipeline/kpi_formulas.py`, shared by both pipelines)

```text
analytical_margin_pct   = net_position / revenue * 100
cost_recovery_ratio     = revenue / total_cost
revenue_variance_pct    = (actual_revenue - budgeted_revenue) / budgeted_revenue * 100
cost_efficiency_index   = total_cost / activity_volume
overhead_share_pct      = allocated_ssc_cost / total_occ_cost * 100
cost_variance_pct       = cost_variance_abs / budget * 100
```

Every formula replaces a zero denominator with a missing value (`pd.NA`)
rather than raising or returning infinity.

### Currency conversion (`src/currency/converter.py`, `src/currency/repository.py`)

- A stored rate means "1 unit of `from_currency` = `rate` units of
  `to_currency`".
- Cross-currency conversion triangulates through the base currency:
  `cross_rate(A->B) = rate(A->base) / rate(B->base)`.
- Rate selection: `LATEST_ON_OR_BEFORE` for spot conversions; annual flows
  (revenue/cost totals) use `ANNUAL_AVERAGE` by default, switchable to
  `YEAR_END` in `config/settings.yaml`.
- Providers, in priority order: a controlled CSV
  (`config/fx/annual_rates.csv` / `manual_rates.csv`), an ECB downloader,
  or a future custom provider — all write into the single `fx_rates`
  table.
- The dashboard's display-currency conversion is presentation-only
  (`src/dashboard/data.py::convert_columns`); stored base-currency values
  are never altered by it.

## 4.6 Rule-Assisted Decision-Support Layer

**Status: implemented and computed on every pipeline run, but not
displayed in the current dashboard navigation.**

`src/rules/alerts.py::generate_alerts()` evaluates `occ_indicators` and
`psl_indicators` against `alert_thresholds` (12 rules: `cost_overrun`,
`material_variance`, `revenue_shortfall`, `low_cost_recovery`,
`critical_deficit`, `budget_ahead`, `high_overhead`, `data_quality`,
`service_deficit`, `negative_margin`, `high_indirect_share`,
`missing_revenue`) and writes matches to `decision_alerts`, each paired
with a recommended action and escalation path in
`decision_support_actions`. The dedicated Streamlit page for this
(`src/dashboard/views/alerts.py`) still exists and still works if routed,
but `src/dashboard/app.py` no longer includes it in the six-page
navigation — per the explicit brief for this refactor, the backend stays
active; only the page was removed from the UI.

## 4.7 Presentation Layer

Six pages, all sharing one sidebar (`src/dashboard/context.py`) and one
centralised KPI-card component (`src/dashboard/components.py::kpi_card`).

| # | Page (identical name, both languages) | Chart types | Justification |
|---|---|---|---|
| 1 | `01_Vue Exécutive_Synthèse` | KPI ribbon + sparklines; donut (revenue share by category, ≤5 categories); horizontal bars (top-10 services) | Donut answers a share-of-whole question; ranking uses bars, per Few (2004) — length is a more reliable comparison encoding than angle |
| 2 | `02_Résultat_Net` | KPI ribbon; existing category→product matrix; `go.Waterfall` (Revenue → −Direct → −Indirect → Net result) | Waterfall makes a additive decomposition to a total legible in one chart |
| 3 | `03_Analyse des recettes` | KPI ribbon; donut (revenue share by category); 100%-stacked bars (product mix within category) | Donut for share-of-whole; stacked bars for a within-category comparison across products |
| 4 | `04_Analyses des charges` | KPI ribbon; grouped (unstacked) bars (direct vs. indirect by cost centre); donut (2-category direct/indirect split) | Grouped bars for a per-centre comparison; donut only for the single global 2-category share question |
| 5 | `05_Evolution du résultat de 2020 à 2026` | KPI ribbon; multi-line (Top-N + Others) with a period-average reference line | Trend/evolution question — lines, never a pie |
| 6 | `06_Evolution des charges de 2020 à 2026` | KPI ribbon; stacked area (Top-N + Others) with a total-charges overlay line | Trend/evolution question — areas, never a pie |

Colour mapping is centralised in `src/dashboard/viz_theme.py`
(`CATEGORY_COLOURS`/`CATEGORY_COLOURS_EN`, `COST_TYPE_COLOURS`,
`SERIES_PALETTE`) and imported by every page that charts the corresponding
dimension, so a given category renders in the same colour on all six
pages. Favourable/unfavourable variance is never signalled by colour
alone; every variance indicator pairs colour with a direction cue in the
surrounding text/formatting.

## 4.8 Synthetic Dataset Summary

Generated exclusively by `src/db/seed_demo.py` (module docstring: *"Ce
module génère exclusivement des données synthétiques à des fins de
démonstration académique."*), seeded deterministically
(`RANDOM_SEED = 42`).

- **Period**: 2020-2026 (`YEAR_FROM`/`YEAR_TO`), both generators
  (`seed_demo()` for the SSC/OCC/PSL demo pipeline,
  `generate_synthetic_oracle_views()` for the Oracle-views-format CSV
  export).
- **Granularity**: `--granularity annual|monthly` on `seed-demo`/
  `run-demo`; monthly is the default. Annual and monthly are two
  independent simulations of the same trend/seasonality baseline, not a
  re-aggregation of one draw — budgeted amounts still sum exactly (no
  random noise applied to budgets); actual amounts sum approximately
  (independent random factor per period), which is the intended
  "somme(mois) ≈ total annuel" behaviour, verified in
  `tests/test_synthetic_data_integrity.py`.
- **Multi-year trend**: `REVENUE_TREND`/`COST_TREND` dictionaries index
  2020-2026 against a 2022 baseline (1.0) — a 2020 downturn (revenue
  0.80, cost 0.90), 2021 partial recovery, then stabilised growth through
  2026 (revenue 1.22, cost 1.14). Revenue's trend range is deliberately
  wider than cost's — traffic-driven revenue can fall faster than a
  largely fixed, payroll-dominated cost base can be cut.
- **Seasonality**: `COST_WEIGHTS`/`REVENUE_WEIGHTS` (12 monthly weights,
  normalised so `sum(weights) == 12`) — a near-flat cost curve with a
  small Q3 bump (energy/overtime), and a revenue curve peaking in Q2/Q3
  (higher vessel-call frequency in the documented dry-season trade peak)
  with a Q4/Q1 trough. Three recurring, documented seasonal edge cases
  are built in every year: a March channel-access dip (`PSL-NACC`), a
  severe November pilotage slowdown (`PSL-PIL`, triggers the
  `critical_deficit` alert), and a September storage disruption
  (`PSL-STOR`).
- **Multi-currency**: GBP, EUR, USD, XOF source currencies across cost
  centres/services (`CENTRE_CURRENCIES`/`SERVICE_CURRENCIES`); FX drift is
  applied both within a year and year-over-year.
- **Oracle-views-format export**: fabricated `CODE_CC`/`DESC_CC` (6
  generic departments, e.g. `2010`/"Port Operations Department"),
  `FAMILLE`/`SOUS_FAMILLE` (8 generic chart-of-accounts families) and the
  same `CATEGORIE`/`PRODUIT_FINI` service catalogue as the synthetic demo
  pipeline (`docs/SERVICE_CATALOG.md`), in the exact column layout of the
  five real Oracle views.
